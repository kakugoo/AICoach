# Project rules

- Work in small agreed stages; do not start a major stage without the user's decision. Communicate in Russian.
- Never fabricate match data or present demo data as real. Distinguish facts, heuristics, and model assumptions.
- Keep frontend, API, parsing, analysis, and future AI responsibilities separate. Prefer a modular monolith.
- Manual demo analysis must not require a FACEIT profile. Tracking a profile does not prove ownership. Never request a FACEIT password.
- No mandatory paid services; no payment integration or artificial accuracy degradation by tier.
- Validate input, handle errors, avoid secrets in Git, and handle files safely.
- Before substantial changes describe the plan. Preserve unrelated work. Test meaningful business logic and report actual verification and limitations.
- Record non-obvious architectural decisions. Verify library compatibility and CS2 parser behavior before depending on them.
- Follow `docs/design-system.md` and its semantic tokens when changing the interface. Never invent analytics or present future capabilities as available.
