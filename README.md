Приложение, помогающее прогрессировать в видеоиграх

# CS2 Analytics Platform

Локальная версия платформы с регистрацией, входом, личным кабинетом и отслеживаемыми профилями FACEIT и локальной загрузкой демок CS2.

## Требования

macOS, Node.js 20.9 или новее, Python 3.12–3.14 и запущенный Docker Desktop с Compose. Команды ниже выполняются из корня проекта, если не указано иное. Не используйте пример пароля для публичного развёртывания.

## Первоначальная настройка

```bash
cp .env.example .env
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-lock.txt
.venv/bin/python -m pip install --no-deps -e backend
cd frontend
npm ci
cd ..
docker compose up -d
```

Дождитесь запуска базы (`docker compose ps`), затем примените миграции:

```bash
cd backend
../.venv/bin/alembic upgrade head
cd ..
```

Если команда `docker` не найдена, запустите Docker Desktop и завершите его первоначальную настройку. Если CLI ещё не добавлен в PATH, для текущего окна терминала можно выполнить `export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"`. Для постоянной настройки используйте параметры Docker Desktop.

## Запуск

В первом окне терминала:

```bash
cd backend
../.venv/bin/uvicorn app.main:app --reload
```

Во втором окне:

```bash
cd frontend
npm run dev
```

Откройте http://localhost:3000. API доступен на http://localhost:8000, документация — на http://localhost:8000/docs. Используйте `localhost` для обоих адресов: смешивание `localhost` и `127.0.0.1` нарушает работу cookie. `/health` проверяет процесс API, `/ready` дополнительно проверяет базу. Кнопка на странице повторяет проверку `/ready`.

## Аккаунт и кабинет

Откройте главную страницу, выберите «Создать аккаунт», укажите email и пароль длиной от 12 до 256 символов. После регистрации откроется личный кабинет. При обновлении страницы сессия сохраняется; кнопка «Выйти из аккаунта» завершает её на сервере. Вход доступен по ссылке на главной. Подтверждение email и восстановление пароля на этом этапе не реализованы.

Чтобы обновить существующую установку после добавления аккаунтов, из корня проекта выполните:

```bash
.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd backend
../.venv/bin/alembic upgrade head
```

Перезапустите backend и frontend. Тесты аккаунтов создают временные схемы в настроенной PostgreSQL и удаляют их после проверки; база должна быть запущена, а пользователь БД иметь право создавать схемы. Не направляйте тесты на производственную базу.

Для HTTPS настройте `COOKIE_SECURE=true` и `ALLOWED_ORIGINS` в `.env`, например JSON-массив адресов разрешённого frontend. Для локального HTTP оставьте `COOKIE_SECURE=false`. В производстве frontend и API должны быть на одном сайте для работы SameSite-cookie, а CORS — с точным перечнем адресов. `NEXT_PUBLIC_API_URL` задаётся при запуске или сборке frontend; `.env` в корне автоматически читается backend, но не frontend. Для локального запуска используется `http://localhost:8000` по умолчанию.

## Профили FACEIT

В личном кабинете откройте «Игровые профили». Поиск использует точный никнейм; добавление создаёт только отслеживание публичного профиля и не подтверждает владение. Для поиска, добавления и обновления информации нужен серверный ключ официального FACEIT Data API. Просмотр уже сохранённых профилей и удаление из своего списка работают без ключа.

Получите **server-side API key** в [FACEIT Developer Portal](https://docs.faceit.com/getting-started/authentication/api-keys/), затем добавьте в локальный файл `.env` в корне проекта строку `FACEIT_API_KEY=ваш_ключ` и перезапустите backend. Не передавайте ключ в браузер, не вставляйте его в `.env.example` или сообщения и не добавляйте `.env` в Git. При отсутствии ключа приложение продолжает работать и сообщает, что поиск не настроен. Наличие ключа не означает, что он действителен: это выясняется при первом запросе к FACEIT.

После обновления кода примените миграции: `cd backend && ../.venv/bin/alembic upgrade head`. В проекте используется HTTPX, уже зафиксированный в `backend/requirements-lock.txt`.

Ограничение локального сервера: не более пяти внешних операций FACEIT на пользователя и 30 на IP за 15 минут; поиск, добавление и обновление входят в этот лимит. Данные CS2 и Steam ID отображаются только при наличии соответствующих полей в ответе FACEIT. Пароль FACEIT не требуется. Тестовые ответы существуют только в тестах; реальные запросы в них не выполняются.

## Загрузка демок и обработчик

Войдите в кабинет, откройте «Мои матчи» и выберите распакованный файл `.dem`. Архивы FACEIT сначала нужно распаковать. Интерфейс показывает ход загрузки и состояние задачи. Для обработки должен быть запущен отдельный процесс: в третьем окне терминала из корня проекта выполните:

```bash
cd backend
../.venv/bin/python -m app.modules.demos.worker
```

Первоначально установите обновлённые зависимости и примените миграции:

```bash
.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd backend
../.venv/bin/alembic upgrade head
```

Файлы сохраняются локально в `storage/demos/` под случайными именами и исключены из Git. Оригинальное имя используется только для отображения. По умолчанию максимум одной демки — 1 ГиБ, общая квота — 4 ГиБ; их можно настроить в `.env` через `DEMO_MAX_BYTES`, `DEMO_QUOTA_BYTES`, `DEMO_STORAGE_DIR` и `DEMO_TIMEOUT_SECONDS`. Изменения требуют перезапуска backend и обработчика. Нужны свободное место, память и процессорное время: парсер и его зависимости занимают значительное место, а разбор большой демки может быть ресурсоёмким.

Статусы: `uploaded` — приём файла, `queued` — ожидание, `processing` — анализ, `completed` — результат готов, `failed` — ошибка. После ошибки сохранённый файл можно повторно поставить в очередь кнопкой «Повторить». Удаление записи удаляет и локальный файл. Незавершённый временный файл удаляется при ошибке загрузки; при запуске обработчик очищает загрузки, зависшие более 24 часов, и возвращает прерванные задачи обработки в очередь. Для задачи действует ограничение времени, по умолчанию 10 минут. Работает один обработчик, который защищён блокировкой PostgreSQL.

Сначала проверяется сигнатура CS2, затем отдельный процесс парсера пытается прочитать файл. Повреждённый файл может пройти первичную проверку сигнатуры, но будет помечен ошибкой при разборе. Результат появляется только после успешной транзакции. Необходимый процесс обработки нельзя заменять только запуском frontend и API.

**Ограничения первой версии:** показатели вычисляются по событиям всей записи и могут включать разминку, убийства союзников и неполные раунды. Счёт, постоянные составы команд и производные метрики пока не рассчитываются. При недоступных полях показывается «—». Числа не следует считать проверенной турнирной статистикой. Результаты и события изолированы по владельцу загрузки; связи с FACEIT по никнейму нет.

Для проверки на настоящем матче загрузите свой `.dem` через кабинет, дождитесь результата и сравните карту, игроков и события с источником записи. Для необязательного интеграционного теста задайте `CS2_TEST_DEMO` как абсолютный путь к реальной демке и запустите `pytest` в `backend`. Без этого файла тест будет пропущен. Не добавляйте демки в Git.

## Проверки

Из корня проекта:

```bash
cd backend
../.venv/bin/pytest
../.venv/bin/ruff check .
../.venv/bin/alembic current
cd ../frontend
npm run lint
npm run typecheck
npm run build
```

Для ручной проверки состояния остановите базу командой `docker compose stop db` из корня проекта и нажмите «Проверить снова»: страница должна сообщить о недоступности базы. Верните её командой `docker compose start db`. Остановите backend и повторите проверку: страница должна сообщить о недоступности сервера.

Остановка базы: `docker compose down`. Данные сохраняются в томе Docker. Не добавляйте флаг `-v`, если не хотите удалить локальную базу. Если меняете пароль после создания тома, PostgreSQL не применит его автоматически к существующей базе.

Переменные в `.env` предназначены только для локальной разработки; этот файл и файлы в `storage/` исключены из Git. Версии зависимостей зафиксированы в lock-файлах.
