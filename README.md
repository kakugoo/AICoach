# CS2 Analytics Platform

Локальная версия платформы с регистрацией, входом, личным кабинетом и отслеживаемыми профилями FACEIT и локальной загрузкой демок CS2.

## Требования

macOS, Node.js 20.9 или новее, Python 3.12–3.14 и запущенный Docker Desktop с Compose. Команды ниже выполняются из корня проекта, если не указано иное. Не используйте пример пароля для публичного развёртывания.

## Первоначальная настройка

```bash
cp .env.example .env
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-lock.txt
.venv/bin/python -m pip install --no-deps -e backend
cd frontend
npm ci
cd ..
docker compose up -d
```

Дождитесь запуска базы (`docker compose ps`), затем примените миграции:

```bash
cd backend
../.venv/bin/alembic upgrade head
cd ..
```

Если команда `docker` не найдена, запустите Docker Desktop и завершите его первоначальную настройку. Если CLI ещё не добавлен в PATH, для текущего окна терминала можно выполнить `export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"`. Для постоянной настройки используйте параметры Docker Desktop.

## Запуск

В первом окне терминала:

```bash
cd backend
../.venv/bin/uvicorn app.main:app --reload
```

Во втором окне:

```bash
cd frontend
npm run dev
```

Откройте http://localhost:3000. API доступен на http://localhost:8000, документация — на http://localhost:8000/docs. Используйте `localhost` для обоих адресов: смешивание `localhost` и `127.0.0.1` нарушает работу cookie. `/health` проверяет процесс API, `/ready` дополнительно проверяет базу. Кнопка на странице повторяет проверку `/ready`.

## Аккаунт и кабинет

Откройте главную страницу, выберите «Создать аккаунт», укажите email и пароль длиной от 12 до 256 символов. После регистрации откроется личный кабинет. При обновлении страницы сессия сохраняется; кнопка «Выйти из аккаунта» завершает её на сервере. Вход доступен по ссылке на главной. Подтверждение email и восстановление пароля на этом этапе не реализованы.

Чтобы обновить существующую установку после добавления аккаунтов, из корня проекта выполните:

```bash
.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd backend
../.venv/bin/alembic upgrade head
```

Перезапустите backend и frontend. Тесты аккаунтов создают временные схемы в настроенной PostgreSQL и удаляют их после проверки; база должна быть запущена, а пользователь БД иметь право создавать схемы. Не направляйте тесты на производственную базу.

Для HTTPS настройте `COOKIE_SECURE=true` и `ALLOWED_ORIGINS` в `.env`, например JSON-массив адресов разрешённого frontend. Для локального HTTP оставьте `COOKIE_SECURE=false`. В производстве frontend и API должны быть на одном сайте для работы SameSite-cookie, а CORS — с точным перечнем адресов. `NEXT_PUBLIC_API_URL` задаётся при запуске или сборке frontend; `.env` в корне автоматически читается backend, но не frontend. Для локального запуска используется `http://localhost:8000` по умолчанию.

## Профили FACEIT

В личном кабинете откройте «Игровые профили». Поиск использует точный никнейм; добавление создаёт только отслеживание публичного профиля и не подтверждает владение. Для поиска, добавления и обновления информации нужен серверный ключ официального FACEIT Data API. Просмотр уже сохранённых профилей и удаление из своего списка работают без ключа.

Получите **server-side API key** в [FACEIT Developer Portal](https://docs.faceit.com/getting-started/authentication/api-keys/), затем добавьте в локальный файл `.env` в корне проекта строку `FACEIT_API_KEY=ваш_ключ` и перезапустите backend. Не передавайте ключ в браузер, не вставляйте его в `.env.example` или сообщения и не добавляйте `.env` в Git. При отсутствии ключа приложение продолжает работать и сообщает, что поиск не настроен. Наличие ключа не означает, что он действителен: это выясняется при первом запросе к FACEIT.

После обновления кода примените миграции: `cd backend && ../.venv/bin/alembic upgrade head`. В проекте используется HTTPX, уже зафиксированный в `backend/requirements-lock.txt`.

Ограничение локального сервера: не более пяти внешних операций FACEIT на пользователя и 30 на IP за 15 минут; поиск, добавление и обновление входят в этот лимит. Данные CS2 и Steam ID отображаются только при наличии соответствующих полей в ответе FACEIT. Пароль FACEIT не требуется. Тестовые ответы существуют только в тестах; реальные запросы в них не выполняются.

## Загрузка демок и обработчик

Войдите в кабинет, откройте «Мои матчи» и выберите файл `.dem`, `.dem.zst` или `.zst` от FACEIT. Интерфейс показывает ход загрузки и состояние задачи. Для обработки должен быть запущен отдельный процесс: в третьем окне терминала из корня проекта выполните:

```bash
cd backend
../.venv/bin/python -m app.modules.demos.worker
```

Первоначально установите обновлённые зависимости и примените миграции:

```bash
.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd backend
../.venv/bin/alembic upgrade head
```

Файлы сохраняются локально в `storage/demos/` под случайными именами и исключены из Git. Оригинальное имя используется только для отображения. По умолчанию максимум одной демки — 1 ГиБ, общая квота — 4 ГиБ; их можно настроить в `.env` через `DEMO_MAX_BYTES`, `DEMO_MAX_UNCOMPRESSED_BYTES`, `DEMO_QUOTA_BYTES`, `DEMO_STORAGE_DIR` и `DEMO_TIMEOUT_SECONDS`. Сжатые файлы хранятся оригиналами; распакованная копия создаётся только на время обработки. Изменения требуют перезапуска backend и обработчика. Нужны свободное место, память и процессорное время: парсер и его зависимости занимают значительное место, а разбор большой демки может быть ресурсоёмким.

Статусы: `uploaded` — приём файла, `queued` — ожидание, `processing` — анализ, `completed` — результат готов, `failed` — ошибка. После ошибки сохранённый файл можно повторно поставить в очередь кнопкой «Повторить». Удаление записи удаляет и локальный файл. Незавершённый временный файл удаляется при ошибке загрузки; при запуске обработчик очищает загрузки, зависшие более 24 часов, и возвращает прерванные задачи обработки в очередь. Для задачи действует ограничение времени, по умолчанию 10 минут. Работает один обработчик, который защищён блокировкой PostgreSQL.

Сначала проверяется сигнатура файла, затем отдельный процесс парсера проверяет и разбирает распакованную демку. Zstandard поддерживает один полный фрейм; повреждённые и содержащие дополнительные данные архивы отклоняются. Повреждённый файл может пройти первичную проверку сигнатуры, но будет помечен ошибкой при разборе. Результат появляется только после успешной транзакции. Необходимый процесс обработки нельзя заменять только запуском frontend и API.

**Методика `competitive-2`:** статистика считается по событиям определённых завершённых соревновательных раундов; разминка, распознанный предварительный ножевой раунд и события после завершения матча исключаются. Счёт и команды выводятся только при согласованности снимков игроков, сторон и изменений счёта. Смерть учитывает самоубийства и тимкиллы; убийство союзника не добавляется к K, самоубийство не добавляется к K, ассист засчитывается при совпадении стороны с убийцей. K/D отображается как K/D при D > 0, иначе `—`. Сложные рестарты, замены и овертаймы требуют дальнейшей проверки: при недостаточности данных показатели остаются пустыми. Результаты изолированы по владельцу; связи с FACEIT по никнейму нет.

Для проверки на настоящем матче загрузите свой `.dem` или `.dem.zst` через кабинет, дождитесь результата и сравните карту, игроков и события с источником записи. Для необязательного интеграционного теста задайте `CS2_TEST_DEMO` как абсолютный путь к реальной демке и запустите `pytest` в `backend`. Без этого файла тест будет пропущен. Не добавляйте демки в Git.

## Диагностика матча

В карточке готового матча доступна кнопка «Диагностика обработки». Защищённый API `/demos/{id}/diagnostics` возвращает исходные события с тиками, причинами исключения, обнаруженными фазами и данными раундов. Сервис не публикует диагностику без авторизации владельца. Для ранее обработанной демки используйте кнопку «Повторить»: прежний результат заменяется только после успешной транзакции; оригинальный файл сохраняется. Для версии `events-1` интерфейс показывает предупреждение об устаревшей методике.

## Проверки

Из корня проекта:

```bash
cd backend
../.venv/bin/pytest
../.venv/bin/ruff check .
../.venv/bin/alembic current
cd ../frontend
npm run lint
npm run typecheck
npm run build
```

Для ручной проверки состояния остановите базу командой `docker compose stop db` из корня проекта и нажмите «Проверить снова»: страница должна сообщить о недоступности базы. Верните её командой `docker compose start db`. Остановите backend и повторите проверку: страница должна сообщить о недоступности сервера.

Остановка базы: `docker compose down`. Данные сохраняются в томе Docker. Не добавляйте флаг `-v`, если не хотите удалить локальную базу. Если меняете пароль после создания тома, PostgreSQL не применит его автоматически к существующей базе.

Переменные в `.env` предназначены только для локальной разработки; этот файл и файлы в `storage/` исключены из Git. Версии зависимостей зафиксированы в lock-файлах.

## Расширенная статистика

Новые результаты содержат версионированную аналитику `advanced-1` и сохраняют прежний `competitive-2`. Чтобы обновить ранее обработанную демку, запустите обработчик и нажмите «Повторить» в списке матчей. Оригинальный файл остаётся на месте; прежний результат заменяется только после успешной обработки. Данные новых показателей хранятся в существующем поле JSON, поэтому дополнительная миграция не требуется.

Показатели рассчитываются по подтверждённым участникам и завершённым раундам; прочерк означает отсутствие достаточных данных либо нулевой знаменатель. ADR — урон здоровью противников на сыгранный раунд, KAST — доля раундов с убийством, ассистом, выживанием или разменянной смертью. Размен требует убийства союзником именно убийцы игрока в том же раунде. Окно по умолчанию — 320 тиков; его можно изменить через `DEMO_TRADE_WINDOW_TICKS` и перезапустить обработчик. Пять секунд соответствуют 320 тикам только при частоте записи 64 тика/с. Формулы, условия участия, ограничения отключений и различия с исходным анализом описаны в `docs/architecture.md`. Новые показатели пока не подтверждены независимым сравнением с FACEIT.

Обзор показывает количество ваших загрузок по состояниям и пять последних матчей. Готовый матч можно открыть из обзора; на странице матча выберите игрока и переключайте вкладки «Обзор», «Дуэли», «Раунды», «CT/T» и «Размены». Неизвестные показатели отображаются прочерком. Загрузка поддерживает выбор и перетаскивание файла; прогресс передачи не является прогрессом анализа.

В разделе «Игровые профили» можно сделать один отслеживаемый профиль основным или убрать этот выбор. API-ключ FACEIT для уже сохранённого профиля не требуется. Назначение не подтверждает владение аккаунтом. Если Steam ID64 основного профиля однозначно найден в демке, обзор показывает сначала счёт его команды, а отчёт выбирает этого игрока. Иначе счёт остаётся нейтральным, а игрока можно выбрать вручную.

После обновления примените миграцию `cd backend && ../.venv/bin/alembic upgrade head` и перезапустите серверы.

## Локальный профиль игрока

В разделе «Игровые профили» откройте «Выбрать игрока из матча», выберите ранее обработанную демку и участника со Steam ID64, затем нажмите «Назначить основным игроком». Имя и Steam ID64 сохраняются локально в PostgreSQL как выбранные данные из демки; это не подтверждает владение аккаунтом. После выбора обзор и отчёты сопоставляют игрока по точному Steam ID64. Если совпадения нет или оно неоднозначно, результат остаётся нейтральным.

Можно изменить или удалить локальный профиль либо переключить персонализацию на отслеживаемый FACEIT-профиль. При переключении локальные данные и сами FACEIT-профили сохраняются; сопоставление по никнейму не выполняется. Для этой функции ключ FACEIT не нужен. После обновления примените миграцию `cd backend && ../.venv/bin/alembic upgrade head` и перезапустите backend и frontend.
